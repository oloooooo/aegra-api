# 对象存储（S3）操作手册

管三件事：**空间知识怎么进 S3**、**会话大表怎么上传**、**所有与对象存储有关的配置在哪里改**。
决策记录见 [adr/0015](./adr/0015-large-tables-in-object-storage.md)（会话文件）与
[adr/0016](./adr/0016-spaces-in-object-storage.md)（空间知识）。

## 0. 什么进 S3、什么不进

| 内容 | 存哪 | 生命周期 |
|---|---|---|
| 会话文件里的 **md** | LangGraph Store（**不进 S3**） | 72h 孤儿 TTL + 删会话即删 |
| 会话文件里的 **xlsx** | S3 `sessions/{h(identity)}/{thread_id}/…` | 删会话即删 |
| 表索引 `.sqlite`（由 xlsx 派生） | S3 同前缀 + 本机缓存 | 可丢，删了自动重建 |
| 空间知识（`knowledge/`） | S3 `okf/…`（`okf.backend: s3` 时读本地镜像） | 随空间 |

## 1. 起对象存储

本机/Docker（SeaweedFS，S3 协议）：

```bash
MSYS_NO_PATHCONV=1 docker run -d --name seaweedfs \
  -p 8333:8333 -p 9333:9333 -p 8888:8888 \
  -v seaweedfs-data:/data \
  chrislusf/seaweedfs server -s3 -dir=/data
```

- **Windows + Git Bash 必须加 `MSYS_NO_PATHCONV=1`**：否则 `-dir=/data` 会被改写成
  `E:/tools/Git/data`，容器起来就退出（`Check Meta Folder … Writable: no such file or directory`）。
- 端口：`8333` = S3 网关，`9333` = master，`8888` = filer 的 UI。
- 没有配 IAM 文件时网关匿名放行，`S3_ACCESS_KEY/S3_SECRET_KEY` 填任意值即可（签名仍会被接收）。
- bucket 由应用自动建（`blobs.ensure_bucket()`，幂等），也可手工 `aws s3 mb`。

## 2. 配置

参数分两处：**非密钥的在仓库根 `config.yaml`**（同名环境变量仍可覆盖），**凭证只走 `.env`**。
改完重启进程，不用发版。逐键说明见 [configuration.md §3.2](./configuration.md)。

`config.yaml`（与对象存储、大表有关的部分）：

| 键 | 默认 | 作用 |
|---|---|---|
| `s3.endpoint` | 空（空 = 未启用） | 网关地址，如 `http://127.0.0.1:8333` |
| `s3.bucket` | `aegra-blobs` | 桶名 |
| `s3.region` | `us-east-1` | 填什么都行（SeaweedFS 不校验） |
| `xlsx.max_blob_mb` | `10` | **单个 xlsx 的 HTTP 上限**（`session_files.max_upload_mb` 只管 md） |
| `xlsx.max_cells` | `2000000` | 结构性硬闸：超过直接拒收，不静默截断 |
| `xlsx.max_xlsx_files_per_session` | `20` | 每个会话能挂几个表（同名覆盖不占名额） |
| `xlsx.max_md_files_per_session` | `10` | 每个会话能挂几个 md（⚠ 当前未被读取：md 实际按 `session_files.max_files_per_session` = 50 判） |
| `xlsx.max_blob_mb_per_user` | `2048` | 每用户二进制总量（2 GB） |
| `xlsx.cache_dir` | `.cache/xlsx` | 索引与字节的本机缓存，**必须在 OKF 根之外** |
| `xlsx.cache_ttl_days` | `7` | 本机缓存保留天数 |
| `okf.backend` | `local` | `local` 读 `knowledge`；`s3` 读本地镜像 |
| `okf.dir` | `okf` | 空间根目录名（相对 `graphs/`） |
| `okf.mirror_dir` | `.cache/okf` | `s3` 模式的镜像目录 |
| `okf.mirror_ttl_seconds` | `0` | 镜像多久后重新拉；`0` = 不自动刷新 |

`.env`（只有凭证）：

| 变量 | 默认 | 作用 |
|---|---|---|
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | `dev` / `dev` | 凭证（SeaweedFS 未配 IAM 时任意值） |
| `SESSION_SCOPE_SECRET` | `dev-session-scope` | 子 agent 读会话文件的 HMAC 密钥，**生产必须改** |

> boto3 必须用 path-style：给了 `endpoint_url` 之后它仍默认 virtual-host，`aegra-blobs.127.0.0.1:8333`
> 解析不了。代码里已写死 `Config(s3={"addressing_style": "path"})`，自己手写脚本时别忘。

### 2.1 两套部署形态：开发用磁盘、生产用 S3

**关键区别：`okf.backend` 只管“空间知识从哪读”。`s3.endpoint` 管“要不要对象存储”。**
两者独立，所以有三种组合：

| 形态 | `okf.backend` | `s3.endpoint` | 空间知识从哪读 | 上传会话大表 | 适合 |
|---|---|---|---|---|---|
| **纯磁盘**（开发缺省） | `local` | **留空** | `knowledge/` | ❌ 接口 `503` | 写代码、跑单测、不想装 SeaweedFS |
| **混合** | `local` | 填本机网关 | `knowledge/` | ✅ | 只试大表链路 |
| **全 S3**（生产） | `s3` | 填集群网关 | S3 `okf/` 的本地镜像 | ✅ | 多副本部署 |

#### 开发（纯磁盘，不需要 SeaweedFS）

```yaml
# config.yaml
okf:
  backend: local
  dir: knowledge                # 空间根 = knowledge（仓库根，不在代码包里）
s3:
  endpoint: ""                  # 留空 = 对象存储不启用
xlsx:
  cache_dir: .cache/xlsx
```

这一档下：

- 空间里的 xlsx（`/空间名/x.xlsx`）**四个工具照常用**：读本地盘 → 建本机 SQLite 索引。
- **上传大表会返回 503**（没有对象存储可放），其余功能不受影响；md 上传照常（进 Store）。
- 删会话时跳过对象清理（`blobs.configured()` 为假），不会每次删会话都打一条异常日志。
- 不需要配 `S3_ACCESS_KEY/S3_SECRET_KEY`。

#### 生产（空间 + 会话文件都在 S3）

```yaml
# config.yaml
okf:
  backend: s3
  mirror_dir: /var/cache/aegra/okf        # 部署时给绝对路径
  mirror_ttl_seconds: 300                 # 0 = 不自动刷新，只靠 pull 脚本
s3:
  endpoint: http://seaweedfs:8333
  bucket: aegra-blobs
xlsx:
  cache_dir: /var/cache/aegra/xlsx        # 同上：给绝对路径
```

```ini
# .env —— 只有凭证
S3_ACCESS_KEY=…
S3_SECRET_KEY=…
SESSION_SCOPE_SECRET=…                    # 每个部署自己生成，不要用缺省值
```

从开发切到生产，按这个顺序做：

```bash
# 1) 把当前空间内容推到 S3（幂等，可反复跑）
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_push_s3.py --prune
# 2) 改 config.yaml：okf.backend: s3 + 上面那组 s3.* 参数
# 3) 每个副本拉一次镜像（或直接启动，镜像缺失时会自动拉）
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_pull_s3.py
# 4) 自检
PYTHONPATH=. .venv/Scripts/python.exe -m pytest tests/unit/test_okf_mirror.py tests/unit/test_blobs.py -q
```

注意：

- `config.yaml` 里 `s3.endpoint` 默认留空（= 不启用）。要試本机网关就填
  `http://127.0.0.1:8333`；**不起网关就保持空**，否则上传会变成 `503` 而不是“未启用”的清晰降级。
- `xlsx.cache_dir` / `okf.mirror_dir` 默认是相对 CWD 的 `.cache/…`，生产要给绝对路径，
  且**不能落在 OKF 根下**（根散文件对所有登录用户只读共享）。
- `s3` 模式下空间内容改了，必须 `okf_pull_s3.py`（或设 `okf.mirror_ttl_seconds` 让它自己过期），
  否则各副本读到旧内容。

## 3. 上传本地文件

### 3.1 空间知识（`knowledge/` → `okf/` 前缀）

```bash
# 看要传什么
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_push_s3.py --dry-run

# 传（幂等：对象已存在且大小相同就跳过）
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_push_s3.py

# 顺带删掉 S3 上本地已没有的对象
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_push_s3.py --prune
```

让服务读 S3 里的空间知识：

```yaml
# config.yaml
okf:
  backend: s3
  mirror_dir: .cache/okf
  mirror_ttl_seconds: 0     # 0 = 只在镜像缺失时拉；改了空间内容重跑下面的 pull
```

```bash
# 手动刷新镜像（多个副本都跑一次；或设 TTL 让它自己过期重拉）
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_pull_s3.py
```

> 为什么是镜像而不是"直接读 S3"：见 ADR-0016 的「决定变更」。一句话——`BackendProtocol`
> 有 14 个方法（ls/read/grep/glob/…），在对象存储上重写一遍的正确性风险远大于收益，
> 而镜像让 8 个 fs 工具走的还是同一份已测实现。

### 3.2 会话大表（xlsx → `sessions/…` 前缀）

走 HTTP：`POST /custom/uploads/tables`（`multipart/form-data`，字段 `thread_id` + `file`）。

```bash
# 文件名必须是 <空间名>_<表名>.xlsx；空间名决定主管派哪个子 agent，不决定存哪
curl -X POST http://127.0.0.1:2026/custom/uploads/tables \
  -H "Authorization: Bearer $TOKEN" \
  -F "thread_id=$THREAD_ID" \
  -F "file=@./报价表.xlsx;filename=cbam-reporting_报价表.xlsx"
```

成功返回 `201`：

```json
{"name": "cbam-reporting_报价表.xlsx", "path": "/uploads/cbam-reporting_报价表.xlsx",
 "space": "cbam-reporting", "bytes": 4956, "sha256": "…", "indexed": false}
```

错误码：

| 码 | 情况 |
|---|---|
| `404` | 会话不存在或不是你的 |
| `415` | 扩展名不是 `.xlsx` |
| `413` | 超 `xlsx.max_blob_mb` / 超每用户字节配额 / 超每会话文件数 |
| `422` | 文件名非法（控制字符、>200 字符、`.xlsx` 之外）或**空间名不属于你** |
| `503` | 对象存储未配置或不可用 |

要点：

- **`indexed:false` 是正常状态**：索引在第一次调 `xlsx_*` 工具时才建（几十毫秒～几十秒，看表大小），
  建完写回 S3，之后任一实例都能直接命中。
- 同名重传 = 覆盖（PUT 语义）。同内容重传命中同一个 key，不重建索引。
- 子 agent 只有在**同一条会话**里才读得到（靠派活时签发的 `session_scope` 凭证）。
- 删除入口是删会话（`DELETE /threads/{id}`）：清 PG 行 + 清整个 `sessions/{h}/{thread}/` 前缀。

### 3.3 运维直连（脚本/手工）

```python
import boto3
from botocore.config import Config

s3 = boto3.client("s3", endpoint_url="http://127.0.0.1:8333",
                  aws_access_key_id="dev", aws_secret_access_key="dev",
                  region_name="us-east-1",
                  config=Config(s3={"addressing_style": "path"}))
s3.upload_file("本地路径.xlsx", "aegra-blobs", "tmp/manual/x.xlsx")
```

或者 `aws --endpoint-url http://127.0.0.1:8333 s3 ls s3://aegra-blobs/okf/`。

> 手工放进 `sessions/…` 前缀的**对象不会被任何工具读到**——`session_object` 表里没有对应行，
> 工具查的是那一行。要造会话文件请走 3.2 的接口。

## 4. Key 布局

```
tmp/{uuid4}/{name}                                                 上传中转，7 天生命周期兜底
sessions/{h(identity)}/{thread_id}/{sha256[:16]}/{name}            会话文件字节
sessions/{h(identity)}/{thread_id}/idx/{name}.h{header}.v{BUILD}.sqlite   表索引
okf/<space>/...                                                    空间知识
```

- `h(identity)` 与 Store 命名空间共用 `shared.session.store.identity_digest`（sha256 前 16 位）。
- `{sha256[:16]}` 进路径：并发上传同名不同内容各写各的 key，**不会出现"行说 A、字节是 B"**。
- `v{BUILD}`：索引结构变了就 +1（`graphs/tools/xlsx/index.py` 的 `BUILD`），旧索引自然失效。

## 5. 上限是怎么判的

上传时按这个顺序，每步都比下一步便宜：

1. 会话归属（`404`）；
2. `Content-Length` / `file.size` 超过 `xlsx.max_blob_mb` → `413`，一个字节都不读；
3. 流式读 64 KB：边计数边算 sha256，超线立刻中止（`blobs.put_stream` 自己管分片，能 abort）；
4. 文件名规则 + 空间权限（`422`）；
5. 写序 `tmp → copy → PG 事务 → 删 tmp`；配额在事务里锁用户行判定。

`xlsx.max_cells` 不是上传时判的——上传只流式写字节，服务端不落本地副本，看不到行列。它**第一次调工具时**判：
`openpyxl read_only` 探行列数（实测 27 ms），超了直接报错，**不建索引、不静默截断**。
所以一张“能上传但处理不了”的表不会先跑几十秒再撞超时。

## 7. 排错

| 现象 | 原因 / 处理 |
|---|---|
| 容器起来立刻退出，日志 `Check Meta Folder (-mdir="E:/…")` | Git Bash 改了 `-dir`，加 `MSYS_NO_PATHCONV=1` |
| `botocore ... ConnectTimeout` / `EndpointConnectionError` | `s3.endpoint` 写错或网关没起；先 `curl http://127.0.0.1:8333` |
| `InvalidRequest` / DNS 解析失败里带 `bucket.127.0.0.1` | 没配 path-style（见 §2 末尾） |
| 上传 `503` | 服务进程里 `s3.endpoint` 为空（`config.yaml` 没填，或环境变量 `S3_ENDPOINT` 覆盖成了空）；或者开发形态下本来就不想用对象存储 |
| 分片对象的 `ETag` 不是文件 md5 | 正常：只有单次 PUT 的 ETag 才是 md5 |
| 未完成分片一直占空间 | `blobs.abort_stale_multiparts(86400)`（`upload_fileobj` 那条路拿不到 upload_id，我们已改成自己管分片） |
| 空间文件改了但服务读到旧的 | `okf.backend: s3` 下要重跑 `scripts/okf_pull_s3.py`（或调 `okf.mirror_ttl_seconds`） |
| 索引像是旧的 | 本机缓存 `xlsx.cache_dir` 可整目录删；S3 上的按 `v{BUILD}` 区分 |

## 8. 清理与容量

- **删会话**（唯一正常的删除入口）：`custom/middleware/threads_delete.py` 先删 `session_object` 行，
  再按前缀删 `sessions/{h}/{thread}/`（覆盖字节 + 索引）。任何一步失败只记日志，不把删除变成 500。
- **手工清前缀**：`blobs.delete_prefix("sessions/<digest>/<thread>/")`，幂等。
- **上传垃圾（必须定期跑）**：`scripts/reap_multipart.py` 清两样东西——超过 `--older-than-hours`
  （默认 24h）的 `tmp/` 中间对象，以及超时未完成的分片。两者对象存储都不会自动回收：
  上传写序是 `tmp/` → copy 到正式 key → PG 事务 → 删 `tmp/`，中途崩就留下；分片是
  `upload_fileobj` 拿不到 `upload_id` 的后果。**空跑先看数**：
  `PYTHONPATH=. python scripts/reap_multipart.py --dry-run`。
  挂 cron / 任务计划每几小时跑一次；不跑脚本就用对象的生命周期规则兜底
  （`tmp/` 前缀过期删除 + `AbortIncompleteMultipartUpload` 自动 abort）。
  这是**运维脚本，不是 crons API**——aegra 的定时任务只触发图 run。
- **对账**：PG 的 `sum(size_bytes)` 不含索引与被覆盖的旧对象，物理用量可能是 2 倍
  （`docs/large-files.md` §10 已记为已知限制）。要精确就把 `spaces/`、`sessions/` 前缀逐个
  `list_objects_v2` 累加。
